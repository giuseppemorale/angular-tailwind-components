# Date time picker

`TailwindDateTimePicker` shows **one** read-only field and a panel with calendar, hours and minutes. The control value is a **`Date | null`** (`ControlValueAccessor`).

Changes in the panel stay in draft until the confirm button is pressed — its label follows the configured language — which writes the form value and closes the panel. Closing without applying (a second click on the field) discards them.

In the calendar, clicking the month/year header opens the **year** grid (12 per page) → the **month** grid → days; the arrows change month in the day view, or year range in the year view.

The field text follows the **`format`** string in [Angular DatePipe](https://angular.dev/api/common/DatePipe) syntax (default `dd/MM/yyyy HH:mm`: `MM` = month, `mm` = minutes, `HH` = hours 0–23).

---

## Import

```typescript
import { ReactiveFormsModule, TailwindDateTimePicker } from 'angular-tailwind-components';
```

### Injection token

| Token                        | Type                       | Values          | Default |
| ---------------------------- | -------------------------- | --------------- | ------- |
| `TAILWIND_DATETIME_LANGUAGE` | `TailwindDatetimeLanguage` | `'it'` · `'en'` | `'it'`  |

The CVA value is **`Date | null`**. `writeValue` accepts a `Date`, `null` or `undefined` (reset).

```typescript
@Component({
  imports: [TailwindDateTimePicker, ReactiveFormsModule],
  template: ` <tailwind-datetime-picker

    format="dd/MM/yyyy HH:mm" />`

```

Make sure **`TAILWIND_DATETIME_LANGUAGE`** is provided at application level as shown above; the component needs no extra providers of its own.

## Interface language

Panel labels (weekdays, months, hour, today, confirm) and the default placeholder follow the **`TAILWIND_DATETIME_LANGUAGE`** token. With the default **`dd/MM/yyyy HH:mm`** format the field value goes through **`Intl.DateTimeFormat`** with **`it-IT`** or **`en-US`** depending on the token — no `registerLocaleData`, no import from `@angular/common/locales`. A custom **`format`** goes through Angular **`formatDate`** with **`en-US`**, so textual tokens such as `MMMM` stay in English.

Supported values: **`'it'`** or **`'en'`**. When the token is **not** provided the component falls back to **`'it'`**.

### Recommended setup: global provider

To avoid repeating the provider on every component that uses the picker, register **`TAILWIND_DATETIME_LANGUAGE` once** in the application `providers` array — the same place where you configure the router, the HTTP client and so on.

**Standalone application** (`app.config.ts`):

```typescript
import { ApplicationConfig } from '@angular/core';
import { provideRouter } from '@angular/router';
import { TAILWIND_DATETIME_LANGUAGE } from 'angular-tailwind-components';

export const appConfig: ApplicationConfig = {
  providers: [
    { provide: TAILWIND_DATETIME_LANGUAGE, useValue: 'it' },
    provideRouter(routes)
    // …altri provider globali
  ]
};
```

**Direct bootstrap** (`main.ts`): add the same `{ provide: TAILWIND_DATETIME_LANGUAGE, useValue: 'it' }` object to the `providers` array passed to `bootstrapApplication`.

**Root module** (`AppModule`): the same `provide` entry in the `@NgModule` `providers` array.

Every `tailwind-datetime-picker` in the app then shares the same language. A per-component override is still possible by adding a more specific `providers` entry on the `@Component` or on an intermediate container — Angular resolves upwards through the injector hierarchy — but the global case is the usual one.
