# Table

`TailwindTable` owns the shell, client-side search (an OR across every field of a row), sorting and pagination over `data`. The header is projected as a `<thead>`. The body is defined with **`tailwindTableRow`** on the row template, described below.

---

## Import

```typescript
import { TailwindSortHeaderDirective, TailwindTable, TailwindTableRowDirective } from 'angular-tailwind-components';
```

## Example

<Canvas of={TableStories.Table} />

The default look of **`<thead>`**, **`<th>`** and **`<td>`** — header background, borders, padding, typography — lives in **`table.component.css`** behind **`:where(…)`** selectors inside `@layer components`, so any **Tailwind class** you put on cells and headers (`min-w-*`, `max-w-*`, `w-*`, `truncate`, `p-*`, …) wins over the defaults.

The table is **not framed like a card**: no outer border, no radius. All the separation lives in the content — one rule between the header and the body, one under every row — so a table drops into a page or a card without adding a second frame around the one already there. It keeps `bg-surface`, which the sticky header needs as an opaque plane.

The rule under the **last row** is dropped whenever no pagination bar follows it — an unpaginated table, or an empty one showing the `emptyMessage` — because there is nothing left for it to separate and it reads as a line hanging under the table. With the pager visible the rule stays, as the divider between the rows and the pager.

The header carries no fill either: it is set apart by type — `0.75rem`, `font-weight: 500`, slight tracking, one step lighter than the body — over the same surface as the rows. `stickyHeader` paints `surface` explicitly, because a sticky header without a fill would let the rows scroll through it; the color is the same either way.

The inner `<table>` uses **`table-layout: auto`**, so columns follow their content. Every **`th`** / **`td`** carries a default **`min-width: 7.5rem` (120px)**, from the **`--tw-table-col-min-width`** CSS variable on the `tailwind-table` host. Only the **table** sits in an **`overflow-x-auto`** wrapper; the **pagination** stays pinned below the last row's rule and never scrolls sideways with the columns.

### Toolbar (`tailwind-table-tools`)

With `searchable` on (the default), search and custom actions share a **`flex justify-between`** row. Project content on the right through the **`tailwind-table-tools`** attribute:

```html
<tailwind-table [data]="rows">
  <div tailwind-table-tools>
    <tailwind-button icon="arrow-path">Refresh</tailwind-button>
  </div>
  <thead>
    ...
  </thead>
  <tbody *tailwindTableRow="let row">
    ...
  </tbody>
</tailwind-table>
```

The toolbar also shows with `searchable="false"`, as soon as something is projected into `tailwind-table-tools`.

For columns with long text such as e-mail addresses, use **`max-w-*`** plus **`truncate`** on the cells; for action columns with buttons, **`whitespace-nowrap`**.

```typescript
@Component({
  imports: [TailwindTable, TailwindTableRowDirective, TailwindSortHeaderDirective],
  template: `
    <tailwind-table [data]="rows" [paginated]="true" [pagination]="pagination" [emptyColspan]="2">
      <thead>
        <tr>
          <th tailwindSortHeader sortKey="name">Name</th>
          <th>Email</th>
        </tr>
      </thead>
      <tbody *tailwindTableRow="let row">
        <tr>
          <td>{{ row.name }}</td>
          <td>{{ row.email }}</td>
          <td>{{ row.role }}</td>
          <td>
            <tailwind-tag [color]="row.status === 1 ? 'success' : 'danger'">{{
              row.status === 1 ? 'Active' : 'Inactive'
            }}</tailwind-tag>
          </td>
        </tr>
      </tbody>
    </tailwind-table>
  `
})
export class ExampleComponent {
  rows = [{ name: 'Alice', email: 'a@example.com' }];
  pagination = { totalItems: 1, pageSize: 10, currentPage: 1 };
}
```

## Rows (`tailwindTableRow`)

The component repeats the template for every row of `displayedData()`. The recommended form is a **structural directive on `<tbody>`** — the `*` is what makes Angular expand the template with `let row`:

```html
<tbody *tailwindTableRow="let row">
  <tr>
    <td>{{ row.name }}</td>
    <td>{{ row.email }}</td>
    <td>{{ row.role }}</td>
    <td>
      <tailwind-tag [color]="row.status === 1 ? 'success' : 'danger'"
        >{{ row.status === 1 ? 'Active' : 'Inactive' }}</tailwind-tag
      >
    </td>
  </tr>
</tbody>
```

Each iteration produces its own `<tbody>`, which HTML5 allows. For zebra striping, selection and clicks the template context also exposes `stripedRow`, `selected`, `selectable` and `toggleRow` — see the stories.

**Legacy alternative:** cells only, with no `<tbody>` / `<tr>` in the template:

```html
<ng-template tailwindTableRow let-row>
  <td>...</td>
</ng-template>
```

## Sortable headers (`tailwindSortHeader`)

Only the columns that should sort carry the directive on their **`<th>`**, with the header text as element content and no inner `button`. **`tailwind-table`** intercepts clicks and keystrokes by delegation and applies the sort; no template reference (`#tbl`) and no extra input on the table are needed.

On every **`<th>`** inside the projected **`<thead>`**, `tailwind-table` sets **`scope="col"`** automatically, so the template need not declare it. An explicit value such as `scope="row"` is never overwritten.

## Loading state

With `loading` on, the table draws skeleton rows shaped like the data that is coming instead of a
spinner: a spinner says _something is happening_, a skeleton says _here is what is about to appear_,
and the same wait feels shorter. The number of placeholder cells follows `emptyColspan`.
